# Packaging a community build

`.github/workflows/release.yml` builds the native helper for Windows/Linux/macOS, gets the
Firefox extension signed by Mozilla (AMO *unlisted* channel, not published on addons.mozilla.org),
creates the tag `v<version>` on the commit you chose, and publishes a GitHub release with
the binaries, the signed `.xpi`, license files and checksums.

## One-time setup
1. Create API credentials at https://addons.mozilla.org/developers/addon/api/key/
2. Add them as repository secrets `AMO_JWT_ISSUER` and `AMO_JWT_SECRET`
   (Settings -> Secrets and variables -> Actions).
3. The workflow file must be on the repository's default branch for the "Run workflow" button
   to appear. Afterwards you can run it against any branch.

## Releasing
Actions -> release -> Run workflow -> pick the branch, enter a version (e.g. `0.1.0`).
Every release needs a higher version than the last one, or Mozilla rejects the signing.
Via CLI: `gh workflow run release.yml --ref <branch> -f version=0.1.0 -f prerelease=false`

## Installing (Windows, no admin rights)
`irm https://raw.githubusercontent.com/CrazyWolf13/ts-browser-ext/main/scripts/install.ps1 | iex`

## Notes
- The community build uses its own add-on ID/name and neutral icons (`packaging/icons`),
  not the Tailscale logo. Change `ADDON_ID`/`ADDON_NAME` in the workflow together with the ID
  allowed in `install()` (`ts-browser-ext.go`) and `scripts/install.ps1`.
- `THIRD_PARTY_NOTICES.txt` is generated by `packaging/collect-licenses.sh` from the Go module graph.
